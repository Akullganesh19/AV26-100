## 2024-05-24 — Inaccessible Custom Form Controls
**Found:** Custom radio buttons and checkboxes in the Calculator component lacked semantic roles (`role="radiogroup"`, `role="radio"`), `aria-checked` attributes, and keyboard focus indicators. The underlying checkbox inputs were completely hidden using `display: none` (`hidden` class).
**Why it existed:** The component was built using `<div>`s and `<button>`s styled to look like radio buttons/checkboxes without considering screen reader semantics or keyboard navigation. The native inputs were hidden entirely rather than visually hidden (`sr-only`), breaking keyboard focus.
**Fix:** Added `role="radiogroup"`, `role="radio"`, and `aria-checked` to the custom radio button groups. Changed checkboxes from `hidden` to visually hidden (`sr-only`) and applied `peer-focus-visible` styles to the visual indicators. Added `focus-visible` styles to all interactive custom elements. Added `aria-label` to the custom range slider.
**Learning:** When building custom form controls (radio buttons, checkboxes) using divs or buttons, always apply explicit ARIA roles and ensure keyboard focus is visible. Never hide native inputs using `display: none` if they need to receive focus.
**Watch for:** Other custom form elements (selects, switches, tabs) across the application that might be built with non-semantic elements and missing focus styles.
