## 2025-02-12 — [Global Form Components Lack Accessible Associations]
**Found:** Reusable custom UI components (`Input`, `Select`) in `DiagnosticsCenter` and direct `<input>` tags in `LoginPage` lacked explicit accessible name associations (`htmlFor`/`id`). Additionally, array-mapped inputs in the Parkinson's diagnostic lacked `aria-label`s, icon-only buttons lacked `aria-label`s, and asynchronous submission buttons lacked `aria-busy` indicators.
**Why it existed:** Developers likely focused on visual presentation over semantic HTML structure, and standard HTML elements inside map loops or wrappers were built without dynamically generating unique identifiers or accessibility ARIA roles.
**Fix:** Added standard `id` and `htmlFor` pairings using `React.useId()` to prevent duplicate ID collisions in reusable components, added `aria-busy` to all async buttons, and added explicit `aria-label` and `aria-hidden` attributes to visually impaired or icon-only interactive elements.
**Learning:** Frontend custom wrapper components (like `Input`, `Select`) frequently lack proper accessible labeling. Always ensure a unique `id` is linked to `<label htmlFor={id}>` using React's `useId()` hook (avoid deriving IDs from labels to prevent duplicate ID collisions).
**Watch for:** Other custom form wrappers or icon-only interactive controls across the application that might also lack proper ARIA or semantic associations.
