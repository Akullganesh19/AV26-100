## 2025-02-18 - Making custom UI elements accessible
**Learning:** When creating custom radio buttons using standard `<div>` or `<button>` elements, screen readers don't automatically know they are a group of options. Furthermore, when hiding native `<input type="checkbox">` elements to style custom ones, simply using `className="hidden"` removes them from the accessibility tree, making them un-tabbable for keyboard users.
**Action:** Use `role="radiogroup"` on the parent container and `role="radio"` with `aria-checked` on the individual options for custom radio buttons. When styling custom checkboxes, do not hide the actual `<input>` with `display: none` or `hidden`. Instead, use `className="sr-only peer"` on the `<input>`, place it right before the custom indicator `<div>`, and use `peer-focus-visible` classes on the `<div>` to show keyboard focus styles while keeping the input discoverable by assistive technologies.
