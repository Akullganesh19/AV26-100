## 2025-06-18 — Calculator Form Accessibility Fix

**Found:** Custom UI components (sliders, radios, checkboxes) in `CalculatorSection.tsx` were inaccessible to keyboard and screen reader users due to lacking ARIA roles, un-focusable hidden inputs, and missing visible focus states.
**Why it existed:** The custom components were built visually using standard `div` and `button` elements without prioritizing semantic HTML or native element accessibility patterns. Hidden native checkboxes used `className="hidden"` (display: none), completely removing them from the accessibility tree and preventing keyboard focus.
**Fix:** Added `aria-label` to the range input. Wrapped custom radio buttons in `role="radiogroup"` containers with appropriate `aria-label`s, added `role="radio"` and `aria-checked` to the buttons, and added `focus-visible:ring` styles. For custom checkboxes, replaced `hidden` with `sr-only` to preserve focusability and added `group-focus-within` styling to visually reflect the native input's focus state. Added UX notes in comments above fixes.
**Learning:** When building custom interactive components, never use `display: none` (`hidden`) on native form inputs; always use `sr-only` to keep them focusable by keyboards and screen readers. Roving focus/tabindex is technically more correct for ARIA radiogroups, but the `button role="radio"` pattern is a pragmatic start for basic keyboard accessibility.
**Watch for:** Other custom wrapper components or stylized inputs (like `Input`, `Select`, or toggle switches) that might similarly use `hidden` instead of `sr-only` or lack proper ARIA labels and focus states.
