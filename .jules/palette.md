## 2024-10-25 — Accessible Custom Inputs in Calculator
**Found:** Custom radio buttons, sliders, and checkboxes in `CalculatorSection.tsx` were built without semantic ARIA roles, states, or focus visibility, making them inaccessible to keyboard and screen reader users. The custom checkboxes used `className="hidden"` on the native input, removing them entirely from the accessibility tree.
**Why it existed:** Developers prioritized visual styling using `div` and `button` wrappers to match a specific UI design but neglected to map the native input semantics (like `aria-labelledby`, `role="radiogroup"`, `role="radio"`, `aria-checked`) or handle keyboard focus states (`focus-visible`).
**Fix:** Added `role="radiogroup"` and `role="radio"` with `aria-checked` to custom radio buttons. Replaced `hidden` with `sr-only` on checkboxes and applied `focus-within` styling to their parent labels. Added `focus-visible` styling across all interactive custom components and mapped `aria-labelledby` to the custom slider.
**Learning:** When building custom form controls in React/Tailwind, always retain the semantic state (like `aria-checked`) on the wrapper elements or use visually hidden (`sr-only`) native inputs to maintain both the desired UI and accessibility. Never use `display: none` (`hidden`) on native inputs you want screen readers to interact with.
**Watch for:** Other custom form components (like toggles, custom selects, or complex multi-step forms) throughout the codebase that might be missing ARIA roles or focus rings.
