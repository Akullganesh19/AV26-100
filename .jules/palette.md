## 2024-05-19 - Keyboard Accessibility in Custom Form Controls
**Learning:** In Tailwind, using `className="hidden"` on native form inputs (like checkboxes) removes them from the accessibility tree, which breaks screen readers and keyboard focus navigation entirely. Additionally, custom radio button groups made with `<button>` elements require explicit ARIA roles (`role="radiogroup"` on parent, `role="radio"` and `aria-checked` on children) to be semantically correct for screen readers.
**Action:** Use `className="sr-only peer"` on native inputs instead of `hidden` to keep them in the DOM and visually hidden, while leveraging `peer-focus-visible` on custom sibling elements for keyboard focus styles. For custom buttons acting as radios, always supply `role="radiogroup"` and `role="radio"`.
