## 2025-02-27 - Rate Limit Bypass via Spoofed Unverified Claims
**Vulnerability:** The rate limiting key function `get_user_id` in `backend/app/api/deps.py` extracted the `sub` claim from the Authorization header using `jwt.get_unverified_claims(token)`. An attacker could generate spoofed JWTs with continuously rotating `sub` values (since the signature was ignored at this stage) to completely bypass user-based rate limits.
**Learning:** Functions that parse tokens for identifier extraction *before* full authentication (e.g., for early middleware like rate limiting) must still cryptographically verify the token, otherwise the identifier can be arbitrarily manipulated by the client.
**Prevention:** Never trust unverified JWT claims for security controls like rate limiting. Either verify the token signature before extracting the identifier, or fall back to a robust, non-spoofable identifier like the client IP address if verification fails or is too costly for the specific middleware layer.
