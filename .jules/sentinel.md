## 2024-05-18 — [CRITICAL/HIGH] Fix Privilege Escalation and Information Leakage in API Endpoints
**Found:** User creation endpoints lacked explicit definition of non-privileged roles, allowing a malicious user to assign themselves the `sysadmin` or `admin` role through a JSON payload in a Mass Assignment attack. Several API endpoints in `clinical.py`, `districts.py`, and `predict.py` directly returned `str(e)` in standard `HTTPException` responses, exposing internal system details via Information Leakage.
**Why it existed:** New object instantiations from the `UserCreate` object were directly parsing and setting fields including `role` which were defaulted to `UserRole.OFFICER` only in schema parsing but allowed overwrites by malicious payloads. The lack of standard logging implementation resulted in developers returning `str(e)` in error handlers for debugging convenience.
**Fix:** Modified `app/api/routes/auth.py` to explicitly enforce `UserRole.OFFICER` overriding any user-supplied role during registration. Modified endpoints in `app/api/routes/clinical.py`, `app/api/routes/districts.py`, and `app/api/routes/predict.py` to intercept errors using `logger.error` internally, and instead return a safe fallback message to the user ("Internal Server Error" or "Inference engine failure").
**Learning:** Pydantic object creation needs explicitly mapped fields on object instantiation to prevent overwriting of internal attributes, rather than relying on schema defaults. Return of exceptions must be sanitized with a logging wrapper to prevent Information Leakage in the HTTP response.
**Watch for:** Other object creation endpoints that might directly deserialize a schema (Mass Assignment). Other routes that might capture global `Exception` objects and inject them into `HTTPException` string templates (Information Leakage).
