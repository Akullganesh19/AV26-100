## 2026-06-30 — Concurrent Batch Prediction InterfaceError & JSON Serialization
**Attacked:** `PredictionService.predict_batch` and `PredictionService.predict_single`
**Found:** 1) `predict_batch` used `asyncio.gather` on `predict_single` while sharing the same `AsyncSession`. Since SQLAlchemy `asyncpg` does not support concurrent operations on the same connection, this caused an `InterfaceError: another operation is in progress` and completely crashed the `list_districts` API endpoint. 2) In `predict_single`, saving `feature_snapshot` directly from Pandas `.to_dict()` sometimes injected `Decimal` or `numpy.number` values (like temperature or rolling std). Since the default JSONEncoder does not serialize these types, it crashed with `TypeError: Object of type Decimal is not JSON serializable`. 3) The `Prediction` model index configuration mismatched `on_conflict_do_nothing` which crashed duplicate checks.
**Severity:** 🔴
**Fixed or flagged:** Fixed. Updated `predict_batch` to use an isolated `SessionLocal` for each concurrent operation. Added `sanitize_for_json` utility to convert decimals/numpy numbers to float before writing to the DB. Also corrected `index_elements` in `on_conflict_do_nothing`.
**Systemic pattern:** Using single database sessions across `asyncio.gather` concurrent tasks in other batched API endpoints. We should ensure new `SessionLocal()` is yielded per task if using gather. Also watch for pandas-to-sqlalchemy json boundary failing on numpy types and Decimals.
