## 2024-05-24 - [Fix Time-of-Check-to-Time-of-Use (TOCTOU) file read vulnerability]
**Vulnerability:** `joblib.loads()` is used which does not exist in `joblib` version 1.4.2 (as listed in requirements.txt), and the previous code uses `joblib.loads()` and failed. But more importantly, the vulnerability here is reading the file contents from disk directly to compute its hash, and if it matches, using `joblib.load(path)`. But the file on disk can be modified after the hash check, and loaded, which is a TOCTOU. Wait, the code actually does `return joblib.loads(content)`. This is already attempting to prevent TOCTOU because it uses the already-read `content`. But since `joblib.loads()` doesn't exist, it will crash. We need to fix this using `io.BytesIO`: `return joblib.load(io.BytesIO(content))`.
**Learning:** For secure joblib deserialization after verifying a file's integrity in memory, be aware that `joblib.loads()` does not exist. Instead, you must use `joblib.load(io.BytesIO(content))` to load the verified byte content. Doing so also prevents Time-of-Check-to-Time-of-Use (TOCTOU) file read vulnerabilities caused by re-reading the file from disk after verification.
**Prevention:** Avoid re-reading a file from disk after verifying its content. If using `joblib`, use `io.BytesIO(content)` to load from memory instead of falling back to `joblib.load(filepath)` which would create a TOCTOU window.
