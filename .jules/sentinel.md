## 2025-03-01 — Privilege Escalation & Fail-Open Authentication Risk
**Found:** Mass assignment (Privilege Escalation) in the registration endpoint and a Fail-Open Authentication pattern in `deps.py`.
**Why it existed:** The `UserCreate` Pydantic model blindly passed all provided fields (like `role`) when instantiating `User` in `auth.py`. In `deps.py`, catching `Exception` indiscriminately around Redis revocation list checks swallowed Redis connection errors and allowed authentication to proceed (fail open).
**Fix:** Hardcoded `role=UserRole.OFFICER` when creating a new `User` in `auth.py` to prevent unauthorized role assignment. Refactored `get_current_user` in `deps.py` to catch specific exceptions (`jose.exceptions.JWTError` and `redis.RedisError`), throwing an explicit `HTTPException` with status code 500 when Redis fails to ensure the authentication infrastructure fails closed instead of open.
**Learning:** Never trust client-provided payloads for critical fields like `role` or `is_active` without explicitly overriding or filtering them before saving to the database. External dependencies used for security checks (e.g., Redis for JWT revocation) must fail closed (deny access or return 500) if they are unavailable.
**Watch for:** Other endpoints passing `**user_in.dict()` directly into SQLAlchemy model instantiations, or broad `except Exception:` blocks used around security validations across the codebase.
