## 2024-05-18 — PII and Sensitive Data Leakage in Application Logs
**Data traced:** Email, Password, Clerk ID, SSN, Password Hash (and generally PII).
**Exposure found:** Standard application logging (e.g. `logger.info`, `logger.error`) lacked comprehensive redaction rules. User emails and sensitive data could be inadvertently logged out in plaintext to standard output whenever exceptions contained it or when `extra={}` params were used with raw PII.
**Fix:** Modified `backend/app/core/logging.py` to route all standard `logging` messages through `structlog`. Added a custom, thread-safe `redact_pii_processor` that recursively scrubs dictionary keys matching sensitive patterns (`email`, `password`, `ssn`, `clerk_id`, `password_hash`) and automatically masks any email patterns in strings. It creates a new structure instead of mutating the existing event_dict, avoiding corruption of live application state, and successfully tracks references to avoid `RecursionError` in cyclically referenced objects.
**Coverage confirmed:** Verified visually that `structlog` automatically hooks standard logs and redacts configured keys and strings using a local script, and then ran the full `pytest` suite locally against Postgres/Redis to ensure the new structlog setup causes zero regressions in normal system behavior.
**Still exposed elsewhere:** Database backups and caches might still retain raw values but are structurally inaccessible from plain text observability logs.
