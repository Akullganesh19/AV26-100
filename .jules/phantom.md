## 2024-05-24 — [Request Coalescing in API Client]
**Gap found:** Multiple components (e.g., Dashboard, TacticalAlerts) could independently trigger identical GET requests to the backend simultaneously during page loads or uncoordinated component mounts. This wastes network bandwidth and database resources (the "thundering herd" problem).
**Why it existed:** Standard Axios clients don't deduplicate simultaneous requests by default, and `React Query` was only used in some components (leaving others like `DiagnosticsCenter` raw), while even with React Query, initial hydration across multiple disconnected components can still trigger concurrent fetching.
**Built:** Implemented invisible Request Coalescing inside `frontend/src/api/client.ts` by intercepting `apiClient.get`. It intercepts the `get` method, tracks in-flight requests in a `Map`, uses a deterministic cache key generated by sorting query parameters, and returns a shared promise for concurrent requests.
**Hot path affected:** Any GET request across the entire application, especially high-volume endpoints like `/alerts/` and `/districts/`.
**Measurable improvement:** Reduces redundant network requests significantly. If two components fetch `/alerts` at the exact same moment, only one network request fires and both components resolve simultaneously when the data returns.
**Next opportunity:** Implement a true cache layer with stale-while-revalidate for static data like user profiles and scenario configurations.
