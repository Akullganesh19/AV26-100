## 2024-05-24 — Request Coalescing

**Gap found:** The frontend HTTP client `apiClient` (`axios`) was naive, processing every `get` call as a distinct network request. If a page or multiple components requested the exact same resource concurrently, multiple identical network requests were dispatched.
**Why it existed:** The default behavior of `axios` is to execute every requested call, which is straightforward but can lead to unoptimized network waterfalls and redundant server hits under heavy UI composition.
**Built:** Request coalescing for identical concurrent GET requests. Intercepted `apiClient.get` and introduced an `inFlightRequests` Map to deduplicate concurrent identical network requests. A deterministic cache key is generated by sorting query parameters, ensuring identically configured requests are properly merged into a shared promise.
**Hot path affected:** Any dashboard or data-rich view (like StrategicMap or DiagnosticsCenter) that composes multiple components fetching from identical read-only endpoints on mount.
**Measurable improvement:** Reduces redundant concurrent HTTP GET requests by returning the identical pending promise, minimizing network latency, bandwidth usage, and unnecessary backend processing load.
**Next opportunity:** Implement a robust Stale-While-Revalidate (SWR) cache layer to further defer synchronous network blocking on subsequent identical data requests across page transitions.
