## 🔭 Future-Proofing Migration

**What:** Migrated `python-jose` to `PyJWT[crypto]` across the backend API dependencies and security core modules.
**Risk it eliminates:** `python-jose` is abandoned, no longer receives security updates, and would become a vulnerability and incompatibility risk for future development.
**Why now:** Immediate migration avoids accumulating technical debt and ensures standard, maintained JWT parsing handles authorization moving forward.
**Migration approach:** Swapped `python-jose` for `PyJWT[crypto]` in `requirements.txt`. Refactored `jwt.get_unverified_claims()` to `jwt.decode(options={"verify_signature": False, "verify_exp": False, "verify_aud": False, "verify_iss": False})` in `backend/app/api/deps.py`. Ensured `HTTPException`s from token revocation aren't inadvertently swallowed by blanket `except Exception:` handlers, catching `jwt.PyJWTError` where appropriate. (Verified that PyJWT natively supports decoding RS256 with the existing string-based PEM configuration).
**Remaining:** None.
**Next session:** Complete.
